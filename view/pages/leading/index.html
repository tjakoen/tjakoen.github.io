Leadership

What it means: setting the direction and getting people moving on it without having to order them to.

I lead by showing, not assigning

I shelved a people-management app I had spent a month on, rebuilt the useful part in an afternoon as a dashboard, and demoed it to the team. Within two weeks two engineers had built tools of their own. Nobody assigned them.

The note: I showed my team a dashboard →

I bring in change with the evidence attached

I introduced an automated reviewer to the team in a twenty-minute talk built from every time it had been wrong, not from what it got right.

The talk: Every time it was wrong →

Impact

What it means: the team ships more and waits less because of what I changed, and I can show the numbers.

I cut review wait from most of a day to three hours

I built a pull request review kit for the team. The slowest quarter of pull requests used to wait 17.6 hours for a first review; now they wait 3.0. Approval stayed with a human, and the note counts the one production break that got through anyway.

The note: Seven hundred commits to teach a reviewer it was wrong →

I make the work spread past me

The review kit started as my own tool and became something other managers install for their teams.

Operational excellence

What it means: the work runs the same way on a bad week as on a good one.

I measure whether a safeguard actually runs

I rolled a start-of-session check out across a dozen repositories, then counted. In one project it had run once in 165 sessions. The cause was structural, not discipline, and I say in the note that I blamed discipline first.

The note: The check ran once in 165 sessions →

I put one process under every repository

One plan format, one health check at session start and in CI, one run record and a second-pass verification, shared by a dozen codebases.

Part two · the workflow

Building multi-model AI workflows

The tools behind the management work are a workflow I built and run every day. It is a cycle, and no single model is load-bearing in it: Claude, Codex and DeepSeek take turns writing, and the parts that keep the work honest stay the same whichever one runs. Each stage is explained under the diagram.

1 · Brief

Every session starts from a written plan and the same instruction file, so the model begins from what the last session decided rather than from a blank page. A new machine is set up from one prompt.

The note: Set up the loop with one prompt →

2 · Write

Claude, Codex or DeepSeek does the typing. Which model runs is a routing decision about cost and fit, not a loyalty, because the rules around it do not change.

The note: The loop outlives the model →

3 · Check

Hooks and gates run whether anyone remembers them or not, and I count whether they actually fired. One that ran once in 165 sessions taught me to measure the safeguard, not trust it.

The note: The check that never ran →

4 · Review

A second model reviews the work the way I would, and it never approves anything; a person does. On the team, this took the slowest reviews from 17.6 hours to 3.0.

The note: The reviewer that learned to be wrong →

5 · Learn

Every miss is logged and turned into a rule, so the next brief is better than the last. A count in August found 503 commits, each co-authored with an AI. The belief under all of it is that AI multiplies the engineer you already are.
