Type what a page should hold, and a fixed, code-owned set of GRAIN blocks decides what actually renders. Picking component names is exactly what a small model gets wrong, so it never gets to pick one. A form is one block among the others now, and it still works the way it always did.

Canvas

Every block below came out of one loop over the composition, and the loop is the whole engine:

for (const block of composition.blocks)
  render(block.component, block.data, block.props)

Layout is three words and only three: full, half and third. A description can ask for two things beside each other and get half, and it can never ask for a grid, a column count or a width, because layout is the part a matcher gets wrong first. Every block sits in a cell that carries its span, so the block itself stays layout-free, which is what grain's own component docs ask of a card or a stat tile.

Nothing on this page was written by the model. The block set decides which components appear, and the words inside each one are the sample content the same table carries, drafted by code. A wording pass is an open seam rather than a shipped feature, and until it exists what lands on a composed page is a developer's writing rather than a generated paragraph.

About the form on this page

The form above is one block, and its insides are the same closed set of fields this page used to be entirely about. Ask for a box to tick and you get one, and the desk can tick it: until 2026-08-14 the vocabulary had no verb that could, because the only verb for a form control writes the control's value, and a tick box's value is what the form submits rather than whether it is ticked, so the write landed, reported success and moved nothing. A tick box carries a different kind of address for exactly that reason.

Fields are grouped by kind, text fields first, then a message box, then choices, then anything to tick. Interleaving them in the order you asked is not supported, on purpose, a v1 limit. The address each field carries sits on the control itself, so the desk writes into a generated field with nothing registered by hand. That was not true when this page was first built: the atoms addressed the label around the control, a label has nothing to write into, and the write was dropped without a word. Building this found it and the atoms were fixed, which is the whole argument for building a demo rather than describing one.

Nothing here submits anywhere. This is a static site, there is no submit control on a generated form, and there is no verb in the vocabulary that could press one.

Can't build yet

Two different reasons live in that list and the difference is worth reading. A shell, a side rail or a top bar is the frame a page sits in rather than content it can hold, so it is refused on principle. Everything else is a gap with a date on it: the component exists, it is documented, and the block set has not grown a template for it yet. A picture is the honest example, because a generated page has no real image to point at and an invented one is a broken picture with a confident name.
