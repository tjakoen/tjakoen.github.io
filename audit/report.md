## What the numbers mean

- **JavaScript response bytes: 30kb–264kb per page** — measured against the local Bun server, which serves these files without compression. Treat them as uncompressed build-size checks, not as the bytes a visitor downloads from GitHub Pages.
- **Wire bytes and request counts describe this local audit run.** They are useful for finding regressions under the same setup, but they are not network-independent or a substitute for measuring the deployed site.
- **TTFB / Load are LOCAL best-case** (no network hop; max load here 655ms) — use them for catching regressions, not as absolute proof. Real-world latency adds to every stack equally.
