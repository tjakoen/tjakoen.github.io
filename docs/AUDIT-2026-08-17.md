# Estate audit, 2026-08-17

A full nine-dimension pass over all seven repos in the estate, run under
[AUDIT-STANDARD](https://tjakoen.github.io/standards/audit-standard): twelve read-only auditors, one
per bounded scope, each handed the whole rubric and each required to name a file and a line.

The theme of this pass has a name. Nine of the ten most serious findings are the same defect wearing
different clothes: **a check that reports success when it could not run**. The estate has built an
unusual amount of machinery to grade itself, and a meaningful share of that machinery is currently
grading nothing while printing OK. That is worse than having no check, because a missing check is
visible and a passing one is not.

## Blockers

### 1. `pantry doctor <dir>` ignores its directory argument

`pantry/cli.ts:157` passes `cwd: process.cwd()` into `runDoctor` and discards `rest[0]`, while the
usage line at `cli.ts:348` advertises `doctor [dir]`. `check` at `cli.ts:151` has the same shape.

Verified. Doctor was run against grain, batch, pantry, bread and greenroom from the portfolio
directory: five byte-identical reports, all grading the portfolio. Greenroom has no upstream branch
at all, yet its report read "up to date with origin/main". Grain has thirteen dirty paths and was
reported as two, which is the portfolio's count. Run from grain's own directory it correctly says
thirteen. A nonexistent path is not refused; it grades the current directory instead. So does
`--help`.

Consequence: the tool that grades the estate has only ever graded whichever directory the caller
happened to stand in. Every cross-repo doctor claim made from the wrong place was a claim about the
portfolio.

### 2. `proof check` is green in a directory with no plans

`proof/loader.ts:56` returns an empty result on a missing `plans/` directory and never distinguishes
that from an empty board, so `runCheck` and `runVerify` report `ok: true` and the CLI exits zero.

Verified in an empty temporary directory:

```
$ bun grain/packages/proof/cli.ts check
0 plans, 0 problems
OK
EXIT_CODE=0
```

`loader.test.ts:39` currently blesses this as the fresh-project case, which is why it has stood. A CI
job pointed one directory off is green forever.

### 3. Grain's model reasoner accepts five verbs it never executes

`grain/packages/grain/ai/model-reasoner.ts:67` switches on four actions. `field.set`, `check.set`,
`block.remove`, `block.span` and `block.move` all pass `validateMove`, fall through `default: break`
at line 78, and return `{ok: true}` having emitted no operation. The comment on that default says the
effect is the reply, which is true for reply-shaped verbs and false for those five.

Verified by reading. No test covers them. Blast radius checked: nothing in the estate calls
`makeModelReasoner` today, because the portfolio's builder builds its own path through
`src/ai/builder-canvas.ts:324`. It ships in published `@tjakoen/grain` regardless, so a consumer
would hit it.

### 4. The hollow-page preflight passes when it scans nothing

`src/component-refs.ts:45` catches every `readdir` failure and returns an empty list, with a comment
that justifies only the missing-root case. If a template directory is misconfigured or unreadable, no
templates are scanned, the missing-component list stays empty, and the check written after the
2026-08-13 hollow-page incident reports clean having looked at nothing. Verified by reading. Line 59
has the same shape but fails loud, so it is fine.

### 5. Pantry's fork detector cannot see seven of the standards

`pantry/doctor.ts:96` lists eight names in `CANON_STANDARDS`. The `standards/` directory holds
fifteen. `doctor.ts:370` skips anything not in the set, so a forked `AUDIT-STANDARD.md`,
`CONFORMANCE.md`, `DECISIONS.md`, `GRAPH.md`, `KICKSTART.md`, `TOUR-STANDARD.md` or `TREE.md` passes
the no-forked-standards check every time. Verified by listing the directory against the set.
`doctor.test.ts:115` only exercises `VOICE.md`, which is in the set, so the gap is invisible to the
test as written. This is the one blocker with a mechanical fix.

### 6. The "Watch me work" demo marks a step done it never did

`src/ai/desk-reasoner.ts:632`: when `openCompose()` returns false the whole draft body is skipped
with nothing said, and line 642 still records the step as done and advances the counter. Same silence
if `fillOp` throws at 637, caught at 638 with a console line only. The mail and contact runners both
announce the identical failure. Verified by reading.

### 7. Crumb lights no lamp and says nothing when a tour target is missing

`crumb/crumb-live.js:248`: `lightStep` no-ops when a step's surface is not on the page. The card still
renders its review and verify prose as though the target existed. `crumb/PLAN.md:85` states that a
tour pointing at a dead surface is a catchable error rather than a silent no-op, and `crumb/check.ts:2`
claims a running host validates targets at tour time. Neither is true of the shipped client.
`crumb-live.test.ts` asserts source text only, so deleting the branch breaks no test.

### 8. Greenroom's legacy test routes bypass the visibility wall

`greenroom/server.ts:746` onward. The `test` table carries a visibility column so a private test can
be walled off, and `pages/editor-api.ts:88` enforces it with `canReadFile`, returning 403 at line 135.
The parallel legacy routes for list, delete, rename, export, import, meta and tags call straight into
`lib/tests-lib.ts` and `lib/tests-share.ts`, which touch the filesystem and never consult the row.
Verified structurally by reading both paths. In platform mode an authenticated non-owner can list,
export the full source of, rename or delete a test marked private.

### 9. Bread's own audit runbook grades a repo that no longer exists

`bread/AUDIT.md:19` tells a session to run `bun test` and `bun run test:e2e` and to grep directories
that were removed in the 2026-07-23 de-submodule. Verified live:

```
$ bun test          error: 0 test files matching ... in --cwd=".../bread"
$ bun run test:e2e  error: Script not found "test:e2e"
```

It also labels `bun run check` as a typecheck when bread's own `package.json` defines it as a doc-drift
linter, so a session that trusts the doc believes types were checked when nothing of the kind ran.

### 10. Bread's roadmap still treats a shipped capability as the pending milestone

`bread/ROADMAP.md:34` frames the live-model milestone as the thing everything builds toward, with its
plans at `doing` and `todo` and every box unchecked. It shipped: `src/ai/desk-reasoner.ts` is a real
local model behind grain's reasoner contract, and `docs/grain/AI-INTERFACE.md` documents it as a
shipped capability. `bunx proof check` independently flags the plan as untouched for sixteen days.

## What actually enforces a standard

Fifteen standards. Their enforcement, as measured:

- Enforced by a hook: GRAPH (the graphify PostToolUse hook, binary present).
- Enforced by a lint, mechanical subset only: VOICE, through `tools/voice-lint.ts`. For `.ts` files
  only five of its ten rules apply, so most of the site's page copy inside source is graded by half a
  standard.
- Enforced in part, at session start only, never in CI: AI-REPO-STANDARD, DECISIONS, SESSION-LOOP,
  LOOP, through `pantry doctor` and the machine-level hooks.
- Advisory nudge only: TOUR-STANDARD.
- Enforced by nobody: AI-DEVELOPMENT, AUDIT-STANDARD, CONFORMANCE, FIGURES, KICKSTART, NOTE-STANDARD,
  README-STANDARD, TREE.

Two of those absences are worth naming. FIGURES bans mermaid on a published page and nothing checks
for mermaid. NOTE-STANDARD requires a frontmatter block, a figure and an exact footer, and nothing
checks for any of the three, which is how the whitepaper came to ship without its footer.

The whole turn-end enforcement layer lives in one machine's `~/.claude/settings.json`. No repo's own
committed settings wire a Stop hook, and no repo's CLAUDE.md says so. A fresh clone, a second
machine, or a CI runner gets none of it.

## Reader-facing defects

The published standards pages carry links that 404. Verified against a running server:

```
$ curl -s localhost:3000/standards/voice | grep -o 'href="\.\.[^"]*"'
href="../content/notes/origin-story.md"
href="../content/notes/whitepaper-one-vocabulary.md"
href="../content/notes/ten-times-zero.md"

$ curl -o /dev/null -w "%{http_code}" localhost:3000/content/notes/origin-story.md
404
```

`src/content.ts:64` rewrites bare filenames and `(grain|batch)/docs/*.md` and nothing else, so any
link carrying a `../` segment ships raw. It hits `/standards/voice`, `/standards/note-standard`,
`/standards/figures`, and four layer-doc pages where `../PHILOSOPHY.md` renders as
`/grain/PHILOSOPHY.md`, also 404 (verified).

Three repos link to `blob/main/PHILOSOPHY.md` at the portfolio root. That file lives at
`docs/PHILOSOPHY.md`; there is nothing at the root (verified). The wrong path sits in
`bread/CLAUDE.md:39`, `bread/AUDIT.md:7` and `project/README.md:26`, while the correct one sits in
`bread/DOCS.md:11`, `bread/README.md:67` and `project/CLAUDE.md:22`.

`content/notes/whitepaper-one-vocabulary.md` ends on its references with no sign-off footer. The other
nine notes carry it and NOTE-STANDARD names the whitepaper explicitly.

## The rest, by repo

**Portfolio.** Two oversized functions hide the failures inside them: `decide()` at
`src/ai/desk-reasoner.ts:663` runs about 990 lines, `boot()` at `src/ai/builder-canvas.ts:243` about
234. `desk-door.ts` has no unit test at 771 lines, and `canvas-dom.ts:164` holds two
security-relevant guards, a prototype-traversal check and a URL-scheme allowlist, with no test at any
tier. `prompt.ts:160` budgets the visitor's notes against the token window and then never truncates
them, unlike history and context. `field-matcher.ts:526` guards null but not type on the one seam the
model may touch. Note and event files are read and parsed twice per page render
(`src/content.ts:722` and `948`). Four content data files are read with a bare `.json()` at module
top level with no guard.

**Grain.** The design-system dimension is clean: a full hex and inline-style scan over every component
found nothing outside the guarded token test, and the block vocabulary is read from the contract's
closed arrays rather than typed as strings. `ai/reasoner.ts:59` is a 459-line decide function.
`scripts/ai-dispatch.js` refuses loudly for span and move and silently for fill and tick.

**Mill and proof.** `mill/serve.ts:48` re-runs `readdir` on every read, so one index page request
issues N+1 directory listings per request. `proof/serve.ts` has no test at all, and the real git
reader at `proof/verify.ts:48` has never run in the suite, only its fake.

**Crumb and grain-mcp.** Both are the most disciplined code in the estate: strict types, no `any`,
explicit return types, tokens-only CSS, real validation on every MCP tool input and every tour id.
The one blocker above is the exception.

**Batch.** `http/static.ts:38` still falls back to `text/html` for any extension outside its list, so
the class behind the PDF-served-as-text defect is narrowed rather than closed. The traversal
containment check is hand-written twice, at `static.ts:36` and `modules.ts:108`. Four modules with
real branching logic have no colocated test, against the repo's own definition of done.
`audit/audit.ts:136` is dead code whose docstring promises output the function does not produce.

**Pantry.** `app.ts:1285` makes four synchronous filesystem calls per artifact request, blocking the
event loop including the live board stream, where the rest of the repo uses the async equivalents for
exactly that reason. The containment rule is genuinely in one place now: every call site imports from
`paths.ts` and no hand-rolled copy survives.

**Greenroom.** Beyond the blocker: `lib/records.ts:159` joins on `basename`, and `basename("..")`
returns `".."`, while `lib/run-scope.ts:52` fails open for any run key with no matching row. No
directory exists at that level today so nothing is reachable, but the guard is broken rather than
merely untested. `lib/runner.ts:156` strips the AES key and the session secret from a spawned spec's
environment, which is the whole defense against a user-authored test exfiltrating them, and it has no
test. Roles and groups swallow a JSON parse error and render an empty list, where environments
already solved that with a visible error surface. Four plans carry `done` in frontmatter with every
checkbox unticked, which is the exact mismatch the repo's own lint advertises.

**Bread and project.** Both documented command blocks assume `bunx pantry` resolves, and
`@tjakoen/pantry` is not published to npm while an unrelated package named `pantry` is. It works
today only because `node_modules/.bin` is already populated.

## Mechanical fixes

Only two findings across twelve auditors are safe to apply with no judgment call:

1. `pantry/doctor.ts:96`, add the seven missing standards to `CANON_STANDARDS`.
2. `proof/serve.ts:38`, add the missing return type to `createProofHandler`.

Plus three one-word link corrections: `bread/CLAUDE.md:39`, `bread/AUDIT.md:7` and
`project/README.md:26` each need `docs/` inserted before `PHILOSOPHY.md`.

Everything else needs a decision about what a failure should say, where a shared helper should live,
or what a doc should now claim.

## Suggested order

1. The two false-green graders, doctor's ignored argument and proof's missing directory. Everything
   else in this report was found by hand because those two could not find it.
2. The published 404s and the missing whitepaper footer. Reader-facing, cheap.
3. CI for grain and batch. Two packages publish unguarded into the repo that serves the site.
4. The four silent no-ops: the model reasoner's five verbs, crumb's dead target, the draft step, the
   component preflight.
5. Greenroom's visibility bypass, which needs a decision about whether those legacy routes should
   exist at all rather than a patch.
6. The stale docs in bread, which currently instruct a session to run a test suite that is not there.

## What this pass did not cover

Named honestly, because an audit that hides its own gaps is the thing it exists to catch.

- 24 of 44 portfolio e2e files were not opened, and three `scripts/*.js` files were not read end to
  end.
- Roughly a third of pantry's source, including all client-side JavaScript, was grepped rather than
  read.
- Most of grain's component `.md` and `.css` pairs were covered only by the whole-tree token scan, not
  read for doc-versus-component accuracy.
- Twelve of the fifteen standards were link-checked and lint-checked but not read end to end for
  internal stale claims. Only VOICE and NOTE-STANDARD got the close read.
- Greenroom's `demo/` fixtures and generated migrations were not read.
- No auditor checked GitHub's actual Actions history. A workflow file existing is not proof it has
  ever run green.
- The fan-out has its own blind spot worth recording: the pantry auditor read `doctor.ts` in full and
  did not notice that the CLI never passes it a directory. Reading a file and running it are
  different acts, and only the second one found that.
