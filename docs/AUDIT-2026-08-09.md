## 2. What changed before the audit could run

**There was no linter in the estate.** Not eslint, not biome, not oxlint, in any repo. The gates were
`tsc --noEmit` plus tests. Lint is a gate rather than an audit dimension, so it was wired first:
oxlint 1.77.0, one shared `.oxlintrc.json` per repo, `bun run lint` in four repos.

bread was deliberately left out: it contains zero source files, and adding a gate that lints nothing
is noise. Its `.oxlintrc.json` and devDependency were reverted after that was confirmed.

The shared config turns off three rules that produced noise without signal here: `no-await-in-loop`
(88 hits, nearly all intentional sequencing in the reasoner), `unicorn/consistent-function-scoping`
(29 hits, style-only), and `no-underscore-dangle`. What is left is real: 40 errors across four repos.

## 6. The owner's question: do the UI tests spot and see properly?

**Mostly yes, with one large hole.** The Playwright suite is not the "assert 200 and move on" shape the
question feared. 210 tests carry 820 assertions, and they routinely check computed `fontFamily`,
`borderStyle`, `gridTemplateColumns`, `zIndex`, bounding boxes, `elementFromPoint` hit-testing, and
no-JS variants. Only five weak `toBeTruthy` style idioms exist in the entire suite.

The hole is the pixel tier. `toHaveScreenshot` appears exactly once, and because of the `100dvh`
overflow-hidden shell it only ever sees the top screenful of each page. Combined with the ratio-based
tolerance on an 85.8M-pixel frame, the one guard that is supposed to catch visual regressions is close
to unable to. That is the single highest-value test fix in the estate.

Thirteen specific tests do not verify what their names claim; they are listed in section 3 and in the
transcript.

## 7a. The security fix

`grain-mcp/README.md` told readers to run `bunx grain-mcp ./dist`. The package is unpublished, but the
**unscoped** name `grain-mcp` is taken on npm at version 1.3.0 by an unrelated project. The documented
command silently fetched and executed a stranger's code inside the reader's agent harness. The usage
block now runs the CLI by path and says why.

Fixed at the class rather than the instance: `private: true` was added to the manifest, so an
accidental publish is now impossible rather than merely discouraged. Previously the only thing keeping
it off npm was a conditional in a workflow file.

**batch.** 12 stale `/framework/` file headers corrected, 10 bare Node specifiers moved to `node:`,
three pieces of dead code removed (`epLines`, `TEXT_EXT`, an unused `rm` import). Gate after: tsc
clean, 50 pass / 0 fail, **lint errors 10 to 0**.

**pantry.** Five of seven applied. Two are real behavior fixes rather than tidying: the heartbeat
catch now reports instead of swallowing every doctor failure, and `cli.ts`'s floating `main()` now
exits with a message and a nonzero code instead of a raw unhandled-rejection stack. Also the doubled
`buildRunsPayload` hoisted, a type predicate replacing a cast in `retrieval.ts`, and a duplicated
`graphDir` expression. Gate after: tsc clean, 290 pass / 3 fail (the same three pre-existing names),
2 lint errors in files the wave never touched.

One skip and one revert, both correct:

- `classifyArtifact` was left alone because the name also appears in a comment, so it failed the
  exactly-once safety check the wave was given.
- The `MillCollection` type-predicate rewrite was applied, broke tsc, and was **reverted**. The
  `as (MillCollection | false | null)[]` cast turned out to be load-bearing for the array literal's
  element inference. That finding was wrong, and the working code was right. Recorded here because an
  audit that never produces a wrong finding is not looking hard enough, and the guard against it is
  the gate, not the reviewer's confidence.
