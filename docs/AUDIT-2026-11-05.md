# Code audit, 2026-11-05: the portfolio and GRAIN

A full quality pass over this repo and the GRAIN monorepo it consumes, run against the nine
dimensions in AUDIT-STANDARD. Five read-only auditors each took one bounded scope with the whole
rubric. Every blocker and every row marked "verified" below was re-read in the code by the
synthesising session rather than taken from an auditor's report.

Scopes: portfolio src/ai; portfolio src (everything else) plus view; portfolio tools, scripts,
e2e, CI and root presentation; grain packages/grain; grain packages mill, crumb, proof and
grain-mcp plus the grain root.

## Could the class have been designed out

Yes, for the blocker class. Every one is the same shape: a loader catches an error and returns
"empty", and a checker reads empty as clean. A single rule closes it in both repos: a check
reports zero inputs as a failure unless it was told that zero is expected. That belongs in the
estate as a lint or a test helper, and in grain as a required CI job. For the token class, the
script used in this audit (every var() checked against variables.css) should become a test in the
portfolio, so an undefined token fails the suite rather than rendering as zero.

## Decisions

The owner chose to fix the blockers first. All five are fixed on the audit date:

- **The red suite.** The three failures were timing budgets, not broken features. Each one passed
  when its file ran alone. Two hit bun's 5s default while reading every served file under a full
  parallel run, and the third ran out of the 3s stream budget during a demo walk that takes close
  to that when the machine is idle. The budgets are wider now, and each one carries a comment
  saying why. The full suite then read 875 pass, 0 fail.
- **The lint gate.** voiceCounts now requires voice-lint's closing summary line and checks that
  its total matches the flags it parsed. That catches both a crash and a format change. A corrupt
  baseline now throws instead of reading as "no baseline yet". The normal run reports the same two
  regressions as before, which shows the cross-check passes on real output.
- **CRUMB and PROOF.** Each loader now carries a reason when its directory could not be read. The
  board and the page routes still show an empty list. crumb check, proof check and proof verify
  now fail on it. Each fix has a regression test, and grain's crumb and proof suites read 148 pass,
  0 fail.

Every major and minor finding stays open, still waiting on an owner decision. The two class-level
gates proposed above, a zero-inputs rule and an undefined-token test, are the cheapest next step.
