# Audit: the portfolio, code and content, 2026-11-24

The owner asked for a standard audit file and a runbook over the code and the content, with the
notes called out. This pass wrote `AUDIT.md`, the repo's own alignment runbook, and
ran it. It is the first runbook this repo has had; the missing file was filed as F12 on 2026-08-13
and F27 on 2026-11-09 and never fixed.

An honest note on the method. The plan was the parallel fan-out in
`standards/AUDIT-STANDARD.md` §4: five read-only auditors, one bounded scope
each. The route check allowed the repository, then the light model pool hit its free limit before a
single auditor returned, and one worktree claim collided. **This pass is therefore one reader, not
five.** That is the failure mode the standard warns about, so the scope that was not read is named
in §5 rather than described as covered. The next pass should fan out once the pool has capacity.

Line numbers are the tree at the start of the pass. Fixes marked landed move a few of them by a line
or two.

## 2. Per-dimension status

1. **Clean code.** One finding, F4, and it is the largest in the report by size. Below the two
   monoliths the functions are short and named for their job; no dead branches found.
2. **DRY.** One finding, F5. The rules that matter are already single-homed: `isPublishedStatus`,
   `COLLECTION_DIRS`, `SITE.origin`, `escapeHtml`, and the note-link rewrite all have one
   definition. Checked by grepping each rule's definition and counting.
3. **Design system.** One finding, F6. Tokens are used almost everywhere; the exceptions are the ATS
   print sheet, the two ant colours and the course hues, and only the last is undocumented. Checked
   with the A3 grep in `AUDIT.md`.
4. **Efficiency.** One finding, F15, and it was the biggest single win in the pass: a request path
   that spawned forty-plus subprocesses, 2.9s a hit. The two module-load caches
   (`src/analytics.ts:49`, `src/content.ts:2103`) are deliberate and documented, the draft-slug cache
   rereads at most every two seconds, and no other per-request synchronous read was found outside the
   small frontmatter reads `shellChrome` documents. Checked by grepping every `readFileSync` in `src/`
   and timing the heaviest routes with `curl`.
5. **Error handling.** One finding, F2, and it is in the tooling rather than the app. The app's
   catches were read one by one: they log with a context string, return a typed fallback, or are
   one of four justified empty catches (clipboard blocked, storage blocked, missing file).
6. **Input validation.** Clean. Model output reaches `JSON.parse` only through guarded helpers
   (`src/ai/block-composer.ts:541`, `src/ai/desk-door.ts:443`), the badge and analytics file reads
   validate shape, and there is no `eval` or `new Function` anywhere in `src/` or `tools/`.
7. **Types.** One finding, F8, minor. No `any`, no `@ts-ignore`, no `@ts-expect-error` outside tests.
8. **Tests.** Four findings, F1, F14, F16 and F17. The suite is 1,052 unit tests, green, and 676 e2e
   tests, whose run is recorded in §6. Five production files have neither a colocated test nor
   an e2e spec that names them:
   `src/ai/canvas-dom.ts`, `src/ai/preview-view.ts`, `src/diagrams.ts`, `src/llms.ts`,
   `src/routes/ai-routes.ts`. The first four are covered indirectly by the canvas and docs specs;
   `llms.ts` is covered by nothing, which is F1.
9. **Readability.** Clean. Every production file carries a header that says what it is and why, and
   the comments that explain a decision match the code under them. No comment was found contradicting
   its code.

## 5. What was not covered

- **The content pass was mechanical, not editorial.** Frontmatter, footer, figure, card, link and
  guardrail rules were checked by command. Nobody re-read 36 notes for a stale claim or a figure that
  no longer matches its number. That is the half of a content audit this pass did not do.
- **`docs/` was spot-checked, not read.** The two repeat findings (F7, F10) were confirmed, and the
  commands a doc names were checked against `package.json` and `tools/`. A full claim-by-claim read
  of `docs/architecture/` and `docs/<layer>/` is still owed.
- **The e2e suite is one run on one machine.** No cross-platform pass, and the visual baselines are
  darwin-only by design.
- **No performance measurement.** Dimension 4 was read, not profiled.
- **The fan-out did not happen.** Five auditors were planned and none returned; see the header.
