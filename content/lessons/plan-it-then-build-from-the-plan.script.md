# Plan it, then build from the plan

Status: DRAFT script for Tjakoen to read aloud and edit. Not yet read or checked by him.

Same format as the Harbor script: each beat is one idea in about 20 to 45 seconds, names the phrase in the note that lights up, and adds the why or the practice instead of repeating the page. If a term like skill, worktree or plan mode comes up, say what it is in a clause and tell the listener to ask their agent. The Claude Academy lessons already covered them.

## Stop 1: A list you can tick off

**Beat 1**
highlight: intro | which of them are done

Two hours in, the AI has touched a pile of files, and you can't say which of your asks are done. That isn't the AI's fault. You've got nothing to point at.

**Beat 2**
highlight: intro | A plan is the thing to point at.

So a plan is the thing to point at. Nothing fancy.

**Beat 3**
highlight: a-plan-is-a-list-you-can-tick-off | A list of small steps, in order

Goal, a list of small steps, and what done looks like for each one. And no code anywhere in it. It's your brief cut into pieces small enough that you can check each one with your own eyes.

**Digest:** A plan is a short file: the goal, small steps in order, and what done looks like for each step. It gives you something to point at.

**Trial:** Think of something you're building and write its goal and two steps, each with a done line.

**Runes:**
small-steps | A list of small steps, in order

## Stop 2: Draft it, edit it, one step at a time

**Beat 1**
highlight: let-the-ai-draft-it-then-you-edit-it | Don't write any code yet.

You don't write the plan from scratch. Hand your AI the brief and the drawing and say this. Plenty of tools have a planning mode for exactly that, and if you're not sure yours does, ask it.

**Beat 2**
highlight: let-the-ai-draft-it-then-you-edit-it | The AI is guessing at your intentions, so the edit is where your judgment goes in.

Now read it like a teammate's proposal. A step called "build the backend" isn't a step, it's a project. Split it. Cut what you didn't ask for. This is where you earn your keep.

**Beat 3**
highlight: one-step-at-a-time | Do step 1 only. Stop and show me when it's done.

Then the habit that makes the whole thing work. Left alone, it'll run through every step and a few extras. Make it stop after one, so you're checking one thing against one line of done, while the mistake is still small.

**Digest:** Have the AI draft the plan and edit it yourself, splitting any step too big to explain in a sentence. Then build one step at a time and check each against its done line.

**Trial:** Ask your AI for a plan with no code yet. Split one step, cut one, then tell it to do step 1 only and stop.

**Runes:**
one-step-at-a-time | Do step 1 only. Stop and show me when it's done.

## Stop 3: Keep it where it survives

**Beat 1**
highlight: keep-it-where-it-survives | If the plan lives only in a chat, it dies when the session does.

Remember the forgetful teammate. Put the plan in a file in the project, and have the AI tick it off as it goes. Tomorrow's session reads it and picks up at step three.

**Beat 2**
highlight: keep-it-where-it-survives | turns that folder into a board

I keep my plans as markdown files, and a tool I built called PROOF turns that folder into a board. PANTRY keeps the board open beside my sessions. I built them for me, because I kept losing track. You don't need either. One file you can read in ten seconds is enough, and if you want a board later, build your own.

**Beat 3**
highlight: a-plan-is-a-guess | you and the AI always have the same one

And be relaxed about it being wrong. It's a guess. Step two will want something you didn't see. Change the plan, tell the AI, update the file. The point isn't that the plan is right. It's that you both always have the same one.

**Beat 4**
highlight: try-this | Do step 1 only, and stop,

Your trial is the whole loop in miniature. Plan with no code, edit it, save it, then step one only, and check it against the done line. In the next lesson, we deal with what happens when the AI says it's finished.

**Digest:** Keep the plan in a file next to the brief so any session can pick it up. It's a guess, so update it when it changes. What matters is that you and the AI hold the same one.

**Trial:** Ask your AI for a plan with no code yet, edit it, save it in your project, then have it do step 1 only and check the result against the done line.

**Runes:**
lives-in-a-file | If the plan lives only in a chat, it dies when the session does.
