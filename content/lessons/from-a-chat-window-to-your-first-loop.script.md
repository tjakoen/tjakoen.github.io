# From a chat window to your first loop

Status: DRAFT script for Tjakoen to read aloud and edit. Not yet read or checked by him.

Same format as the Harbor script: one idea a beat, about 20 to 45 seconds, names the phrase in the note that lights up, and adds the story, the why or the practice instead of repeating the page. This is a journey and an invitation, not a tutorial. What a harness changes, the three files and one check that make the smallest loop, and why any harness works.

## Stop 1: What a project changes

**Beat 1**
highlight: intro | you're the courier between the chat and your files

If you use a chat assistant today, you know the rhythm. Paste code, ask, copy the answer back by hand. It works, but you are the only part that remembers anything, and you are the courier between the chat and your files.

**Beat 2**
highlight: what-changes-when-its-in-your-project | Nothing needs to be pasted.

A harness opens in your project folder. It reads what is there, makes changes, runs commands. Nothing needs to be pasted, and your plan is a file the agent opens instead of a paragraph you retype.

**Beat 3**
highlight: what-changes-when-its-in-your-project | the project becomes the memory

The harness does not fix the forgetting. It gives you somewhere to put what should not be forgotten. So the project becomes the memory, and the loop is the habit of keeping it up to date.

**Digest:** In a chat window you are the courier between the chat and your files. | A harness opens in your project folder, so nothing needs pasting. | The session still forgets, so the project becomes the memory.

**Trial:** Describe in one line what you paste into a chat window today that a harness could simply read from your project.

**Runes:**
intro | you're the courier between the chat and your files
what-changes-when-its-in-your-project | the project becomes the memory

## Stop 2: Three small files and one check

**Beat 1**
highlight: three-small-files-and-one-check | One short file at the top of your project that the agent reads first.

Three small files, then. First, a front door: one short file the agent reads first. It says what the project is, how to run it, and the rules you care about. When the agent does something you did not want, you add a line.

**Beat 2**
highlight: three-small-files-and-one-check | One check.

Second, the plan from the plan note. Third, one check, a single command that says whether the project still works. Pick one, and put it in the front door so the agent runs it without being asked.

**Beat 3**
highlight: three-small-files-and-one-check | The loop itself is the order you use them in.

The loop is the order you use them in. Read the front door and the plan, build one step, run the check, write down what happened, close the session. The next one picks up from the file.

**Beat 4**
highlight: three-small-files-and-one-check | figure: The smallest loop

That is the whole shape. It is boring on purpose, because a boring loop is one you will actually run.

**Digest:** A front-door file is one short file the agent reads first. | The plan file is the one from the plan note, and one check is a single command that says whether the project still works. | The loop is the order you use them in: read, build one step, check, write down what happened.

**Trial:** Open a harness in your portfolio folder, ask it to write a front-door file from what it can see, then edit that file until it is true.

**Runes:**
three-small-files-and-one-check | One short file at the top of your project that the agent reads first.
three-small-files-and-one-check | The loop itself is the order you use them in.

## Stop 3: Any harness, and when to add more

**Beat 1**
highlight: any-harness-works | Work with the agent to make it work.

I use Claude, Codex and DeepSeek, and the same three files work in all of them. If you are not sure what file yours reads, ask it. And if something does not work, do not read it as you doing it wrong. Work with the agent to make it work.

**Beat 2**
highlight: when-you-want-the-full-version | Set Up the Loop With One Prompt

When you want more, there is a note that sets up the whole loop with one prompt, with a checklist, a report and a second reader. It is for people who have run the small version a few times and felt where it runs out.

**Beat 3**
highlight: when-you-want-the-full-version | A loop with five files you use beats one with twenty you don't.

Until then, resist installing more. A loop with five files you use beats one with twenty you do not.

**Beat 4**
highlight: your-turn | If you're writing more plan than code for a week

And where I might be wrong. A loop makes it easy to feel organized while building nothing. If you are writing more plan than code for a week, that is the signal to stop and build.

**Digest:** The same three files work in any harness, with a different name here and there. | If something does not work, work with the agent to make it work. | Resist installing more. A loop with five files you use beats one with twenty you do not.

**Trial:** Run one full pass in your portfolio folder: read, build one step, check, write down what happened. Then list what you would add and leave it out.

**Runes:**
any-harness-works | Work with the agent to make it work.
when-you-want-the-full-version | A loop with five files you use beats one with twenty you don't.
